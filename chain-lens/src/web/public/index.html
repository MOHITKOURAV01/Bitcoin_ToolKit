Bitcoin in plain English

Transaction

A transfer that destroys some coins you control and creates new ones for someone else. Bitcoin has no balances — only coins being re-cut.

Input

A coin being spent, pointing back at the earlier transaction that created it. It must be spent in full.

Output

A newly created coin, locked to whoever can satisfy its script — usually the owner of an address.

Fee & fee rate

The fee is simply inputs minus outputs. The rate (sat/vB) is what you bid per unit of block space.

Weight & vbytes

How much room a transaction takes. Witness data is discounted, so weight ÷ 4 gives vbytes — the number fees are charged on.

SegWit

A 2017 upgrade that moved signatures out of the main transaction body. It fixed transaction-ID malleability and made signatures cheaper.

txid vs wtxid

The txid covers the transaction without signatures; the wtxid includes them. Legacy transactions have no wtxid.

Address types

P2PKH (legacy "1…"), P2SH ("3…"), P2WPKH/P2WSH (SegWit "bc1q…") and P2TR (Taproot "bc1p…") — each a different lock on a coin.

OP_RETURN

An output that provably cannot be spent, used to stamp a small amount of data onto the chain.

RBF

Replace-by-Fee. An input with nSequence below 0xfffffffe says the sender may resend with a higher fee.

Timelocks

Absolute (nLockTime) blocks spending until a height or date. Relative (BIP68) blocks it until a coin has aged.

Undo data

Core keeps a record of every coin a block consumed so it can rewind a block. That is what lets us show input values and fees.
